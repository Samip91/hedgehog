# ADR 008: Cross-cutting hardening — rate-limit generalization, static CSP, JSON logging, hand-rolled PWA SW

**Status:** Accepted
**Feature:** hardening (`docs/features/hardening/`)

## Context

The full loop is code-complete but not deploy-safe (`feature: ship` depends on this).
Four cross-cutting concerns must land without adding risky dependencies on a stack we
can only partially verify from the repo (Next 16.2.10, Prisma 6). Verified from
installed sources: Next's `next.config` `headers()` and `metadata.icons` exist and are
typed. Could **not** verify `@serwist/next`'s Next-16 compatibility (not installed, no
bundled docs); `sharp` is not installed. Zero `console.*` exist in `src/` today.

## Decision

1. **Rate limits — generalize, don't adopt a framework.** Extract the ADR-005 atomic
   fixed-window into `checkRateLimit(bucket, ip, limit, windowSeconds)`;
   `checkHedgeRateLimit` becomes a wrapper preserving its key + behavior. Apply to
   `hedges` (read/save/delete) and `health` with env-tunable limits; leave
   `/api/cron/sync` on its bearer auth (no limiter). Keep fail-open.
   `@upstash/ratelimit` (installed-unused) is a deferred follow-up.
2. **Security headers — static policy in `next.config.ts`, no middleware.** A pure
   `security-headers.ts` module feeds `async headers()` for `source:'/(.*)'`, uniform
   across pages + API. CSP is pragmatic/static: remote scripts `'self'`,
   `frame-ancestors`/`object-src 'none'`, but `'unsafe-inline'` for `style-src`
   (Recharts) and `script-src` (Next streaming, no nonce). Dev-only
   `'unsafe-eval'`/`ws:` gated off the config `phase`. Nonce CSP via middleware is a
   labeled follow-up.
3. **Logging — a small custom JSON logger.** `src/server/log.ts` writes
   `{level,msg,ts,...redacted}` via `process.stdout.write` (preserving zero
   `console.*`), gated by `LOG_LEVEL`. Redacts cookie/creds/token keys, truncates
   prompts to ~100 chars, stamps 500s with a log-only error id, never alters response
   bodies. No pino/winston.
4. **PWA — hand-rolled `public/sw.js` + client registrar; zero-dep icons.** Because
   `@serwist/next`'s Next-16 compat is unverifiable from the repo, the SW is
   hand-rolled: versioned cache, network-first navigations/API with an `/offline`
   fallback, cache-first static, `skipWaiting`/`clients.claim`, registered only in
   production. Icons generated by a committed `zlib`-based script (no `sharp`).

## Consequences

- **Positive:** no new runtime dependency; each concern small, independently testable,
  reversible. The rate-limit seam + header module are trivial to swap for
  `@upstash/ratelimit` / a nonce CSP later. Logging is stdout-only JSON, matching the
  "no observability stack yet" bar. The SW gives real installability + offline shell
  with no unverified-library risk.
- **Negative / accepted:** `script-src 'unsafe-inline'` is weaker than a nonce CSP
  (accepted; nonce is the upgrade). Hand-rolled SW precaches only stable shell URLs
  (hashed `/_next` chunks are runtime-cached, not precached). Icons are solid-color
  placeholders. Fixed-window limits still allow a boundary burst and fail open during a
  Redis outage (inherited from ADR-005).
- **Upgrade path:** (1) swap `checkRateLimit` internals for `@upstash/ratelimit`
  sliding window; (2) move CSP to a nonce-based `middleware.ts`; (3) point `logger` at a
  log-shipping sink or replace with pino; (4) adopt `@serwist/next` once its Next-16
  support is confirmed, or replace placeholder icons with branded art.
